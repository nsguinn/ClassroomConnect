## Behaviour that shapes the design

- **Joining validates project identity.** `FConcertSessionSettings::ValidateRequirements` refuses a different `ProjectName` or `BaseRevision` (`ConcertMain/Source/Concert/Public/ConcertSettings.h:39`). The plugin checks `ProjectName` first only to give students a readable message.
- **Server launch forwards transport settings.** `LaunchConcertServer` passes the editor's UdpMessaging unicast, multicast and `StaticEndpoints` settings, plus `-CONCERTSERVER="<name>"`, to the server process (`MultiUserClientModule.cpp:1435-1464`). Static endpoints are therefore the native fallback when multicast discovery is blocked; no custom transport is needed.
- **Command-line auto-connect exists.** `-CONCERTAUTOCONNECT`, `-CONCERTSERVER=<server name>`, `-CONCERTSESSION=<session name>` are parsed by `ConcertSyncClientModule.cpp:73-81`. Server match is exact on `ServerName` (`ConcertClient.cpp:179`), session match exact on name (`ConcertClient.cpp:214`).
- **Only the session owner is asked to persist.** `DisconnectSession(true)` offers "persist the changes?" only when the leaving client owns the session and it has changes; everyone else just confirms leaving. The dialog defaults to **No** (leave without writing session changes to disk) (`MultiUserClientModule.cpp:723-748`). This is why only the Team Leader may create the session.
- **Session edits live in a sandbox until persisted.** While connected, saves go to a package sandbox and are sent to the server. On leaving, the sandbox is discarded, changed packages are hot-reloaded from disk and session-only packages purged (`ConcertClientPackageManager.cpp:108-157`), so answering No makes the session's work vanish from that editor. Closing the editor while connected persists nothing either: Multi-User shuts its client down on exit without a prompt (`HandleAppPreExit`). The server keeps the work: it archives live sessions on a clean shutdown (`bAutoArchiveOnShutdown = true`) and restores them as live after a crash (`bAutoArchiveOnReboot = false`).
- **Persisting copies saved files only, and only once the server has recorded them.** `IConcertClientWorkspace::PersistSessionChanges` copies sandbox files (`ConcertClientPackageManager.cpp` `PersistSessionChanges` → `PersistSandbox`); unsaved edits are not included. `GatherSessionChanges` lists packages with live transactions or unpersisted head revisions (`ConcertClientWorkspace.cpp:318-335`), and a package saved this frame appears there only after the server round trip — persisting immediately after saving wrote 0 changes in testing. The plugin therefore saves, waits for the saves to be recorded (or for the recorded set to stop changing for 3 s), then persists the union and disconnects with `IConcertClient::DisconnectSession()` (no prompt).
- **Unsaved levels are never shared.** Packages outside a valid long package name root are ignored, "to skip things like unsaved worlds" (`ConcertClientPackageBridge.cpp:38-52`).
- **Stale session-repository locks.** A Multi-User server records the process id that mounted each session repository in `Engine/Programs/UnrealMultiUserSlateServer/Saved/MultiUser/Repositories.json` and treats the repository as locked while a process with that id runs (`ConcertServer.cpp:809`). After a server is killed (crash, End Task), Windows reuses ids; observed here: id 13644 belonged to `conhost.exe`, and every new server failed with "Session could not be created … Repository locked by another process". Classroom Connect clears such locks just before starting a server, only when no Multi-User server process is running at all.
- **Message bus delivery is unreliable by default.** `FMessageEndpoint::Send(Message, Recipient)` uses `EMessageFlags::None`; UDP messaging then drops a whole message if any of its packets is lost. Project copying sends with `EMessageFlags::Reliable`: 33.7 MB went from 30–60 s (chunks lost until a resend timeout) to 0.5 s on one computer. UDP messaging also halves its send window on packet loss (`ComputeWindowSize`, minimum 64 packets), so the copier keeps about 2 MB in flight (`UCC.CopyChunkKB`, `UCC.CopyChunksInFlight`). Byte arrays are serialized as one blob (`WriteByteArrayAsByteStream` is in the default backend flags).
- **Editor close hook.** `IMainFrameModule::RegisterCanCloseEditor` delegates run on every normal close (window X, `CLOSE_SLATE_MAINFRAME`), but not with `-unattended`, which exits before them (`MainFrameHandler.h`).
- **`DisconnectSession(true)` can return true without disconnecting.** If the owner presses Cancel on the persist prompt, it skips the disconnect but still returns true (`MultiUserClientModule.cpp:752-763`). The plugin checks the real connection status afterwards instead.
- **Presence markers are native.** Each remote user is drawn by `AConcertClientDesktopPresenceActor`: a mesh plus a `UTextRenderComponent` name label, tinted with that user's `FConcertClientInfo::AvatarColor`, and a laser pointer while they interact (`ConcertSyncClient/Public/ConcertClientPresenceActor.h`, `ConcertClientDesktopPresenceActor.h`). Markers are drawn only when both users have the **same level** open (`ConcertClientPresenceManager.cpp:316-318`), and recolor live when a user's color changes (lines 358-361). Everyone defaults to white (`FConcertClientSettings` constructor), so the plugin assigns distinct colors with `IConcertClientSession::UpdateLocalClientInfo`, which the server stores and forwards to everyone, including late joiners (`ConcertServerSession.cpp:246-266`).
- **Jumping to a user** (`IConcertClientPresenceManager::InitiateJumpToPresence`) moves the perspective viewport to that user's camera plus an offset (`ConcertClientPresenceManager.cpp:781-829`). `GetPresenceWorldPath` reports which level each user has open; unsaved levels are under `/Temp/`.
- **Auto-connect creates a missing session.** If the named session is not live, auto-connect restores `DefaultSessionToRestore` or **creates** the session (`ConcertClient.cpp:241-264`). So a relaunched student editor must only be given these flags once the team session is known to exist, otherwise the student would become its owner. The plugin's in-editor Join never creates.
- **Server access keys are checked only at discovery.** `UConcertServerConfig::AuthorizedClientKeys` (`ConcertServerSettings.h:82`, `config=Engine`) is compared with the client's `ClientSettings.ClientAuthenticationKey` in `FConcertServer::HandleDiscoverServersEvent` (`ConcertServer.cpp:996`); an empty set answers everyone. The admin requests (list, create, join sessions) do not check it, so the key hides a server from editors that do not send it, nothing more. The key travels in the clear in every discovery message (`FConcertAdmin_DiscoverServersEvent::ClientAuthenticationKey`).
- **The key cannot be passed through `LaunchConcertServer`.** `FServerLaunchOverrides` holds only `ServerName`, and `ParseServerSettings` reads no key from the command line (`ConcertSyncServerModule.cpp:31-110`). Classroom Connect therefore starts the same server program itself with the same arguments Epic builds (`GenerateConcertServerCommandLine`, `MultiUserClientModule.cpp:1405-1472`) plus a per-launch config override, `-ini:Engine:[/Script/ConcertServer.ConcertServerConfig]:AuthorizedClientKeys=<key>`. A single value fills the `TSet` (`UObject::LoadConfig` → `ProcessSetProperty`, `Obj.cpp:3134`); no config file is written. `IsConcertServerRunning` and `ShutdownConcertServer` find servers by program name, so they still work.
- **The client's key can change at runtime, in place.** Discovery re-reads `Settings->ClientSettings.ClientAuthenticationKey` every second (`ConcertClient.cpp:1103-1120`). The settings object must not be replaced while auto-connect runs: `FConcertAutoConnection` keeps a raw pointer to it (`ConcertClient.cpp:53`, `1170`), and `Configure` drops the strong reference to the old object. Classroom Connect edits the key on the client's own settings object (a private copy made by `ParseClientSettings`, `ConcertSyncClientModule.cpp:45-49`), and configures a copy only if the client was given the shared default object (which happens after Multi-User settings are saved, `MultiUserClientModule.cpp:1397-1401`), so the key is never written to a config file.

## Naming scheme

- Session: `UCC-<TeamId>` (e.g. `UCC-Red`).
- Server: `UCC-<TeamId>-<COMPUTERNAME>`. Members find the team host by prefix; two servers with the same prefix mean two leaders and joining stops with an error. Team Ids are alphanumeric, so `UCC-Red-` can never match `UCC-RedX-`.
- Leader-created sessions set `ArchiveNameOverride` to `UCC-<TeamId>-<yyyymmdd-hhmm>`.
